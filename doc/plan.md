## 1. 목적과 확정 방향

개발자가 REST API를 등록·호출·문서화·테스트하고, 여러 요청 데이터 세트를 재사용하며, API 자료를 Git으로 공유하는 도구를 개발한다. `frontend-vue`는 기능 이해를 위한 참고 자료로 활용하며, React 버전은 `frontend-react`에서 개발한다. UI·사용 흐름·폴더 구조·구현 방식은 최신 개발 기획과 React 환경에 맞게 설계한다.

- 프런트엔드는 React + TypeScript + Vite로 개발하고, UI는 shadcn/ui를 사용한다.
- UI 추가 라이브러리는 Tailwind CSS(스타일), Lucide React(아이콘), React Router(라우팅), CodeMirror(JSON·text·문서 원문 편집)를 사용한다. UI 상태는 React 기본 상태로 시작한다. 패키지 버전은 개발 환경 구성 시 상호 호환성을 확인하고 `package.json`과 lockfile에 기록한다.
- Electron 기반 PC 앱으로 제공한다. 사용자는 설치 후 아이콘으로 독립 창을 실행하고 작업 폴더를 선택한다. React UI와 파일·API 실행 기능을 한 앱으로 배포·업데이트한다.
- Renderer는 UI를 담당하고, Preload의 제한된 IPC를 통해 앱 내부 Node.js 기능을 호출한다. 파일·DB·네트워크 접근은 앱 내부에서 처리한다. 상세 기준은 [PC 앱 설계](desktop-design.md)를 따른다.
- 최초 배포는 Windows를 지원한다. 향후 macOS도 지원할 수 있도록 API 호출·파일 포맷·데이터 생성 등 공통 코드와 경로·자격 증명 저장·설치·업데이트 등 OS별 처리를 구분한다. macOS 구현·검증·배포는 후속 범위다.
- 개발 기준은 Node.js 24.22.3·Electron 45.4.1(내장 Node 24.22.3)·Electron Forge 8.0.1이다. 버전 변경은 호환성 검증 후 고정하고 개발 환경 전환은 01.09에서 다룬다.
- 사용자 정보·설정·API 데이터는 사용자 PC와 사용자가 선택한 Git 저장소에서 관리한다.
- API 정의·폴더 구조·문서·payload 세트·공유 환경 템플릿은 사용자 작업 폴더의 파일로 저장한다. 사용자는 외부 Git 도구로 해당 파일을 관리·공유한다.
- 개인 설정·최근 작업 공간·열린 탭·저장 전 초안·API 저장 이력·개인 실행 이력은 앱 사용자 데이터 폴더의 SQLite에 보관한다. Electron 내장 `node:sqlite`를 사용하며 실행 이력의 응답 보관·용량·기간 정책은 08.03에서 정의한다. DB 접근은 앱 내부 전용 Worker가 담당한다.
- 실제 비밀번호·토큰 등 비밀값은 기본 메모리에 두고 공유 파일·개인 DB·초안·저장 이력·로그에 실제값을 기록하지 않는다. 영구 보관 방식은 04.04에서 별도 확정한다.
- 모크 데이터 생성·API 대량 등록·삭제·전체 초기화 기능과 해당 UI는 보류한다. 기능 재개 시 생성 데이터를 사용자 프로젝트의 등록 API로 반복 전송하고, 삭제·초기화도 사용자 지정 API로 수행한다.

## 2. 기획 문서 운영 방법

- 이 문서에는 목적·기능 범위·개발 순서·완료 기준·선행 조건만 기록한다.
- 전체 상태는 [개발 진행 현황](progress.md), 기능별 현재·검증·남은 작업은 연결된 단계별 문서에서 같은 기능 번호로 관리한다.
- 기능 번호는 추적용 고정 ID이며 완료 후에도 재사용하지 않는다. 개발 순서는 아래 단계 요약의 행 순서를 따른다.
- 기본 UI 흐름을 먼저 확인한 뒤 PC 앱 기반과 실제 기능을 연결한다. 문서 UI 검증·테스트 UI·개인 설정 UI는 후속 작업이며 PC 앱 기반 착수의 선행 조건으로 두지 않는다.
- 선행 조건을 충족하면 같은 단계 안에서 작업 순서를 조정할 수 있다. 미확정 라이브러리·아키텍처는 구현 전에 결정한다.
- 합의된 기획이 변경되면 이 문서와 관련 설계 문서를 함께 갱신한다.

## 4. 최초 사용 가능한 버전의 범위

- 개발 순서: 01의 UI 개발 기반 → 12의 기본 UI 확인 → 01.09의 Node 24 전환 → 02의 Electron 실행 기반·IPC·SQLite 검증·작업 공간 → 03~06의 실제 편집·환경·호출·세트 기능 연결. 09의 파일 공유 기반은 파일 저장 구현부터 함께 반영한다. 후속 UI 작업은 PC 앱 기반 착수를 막지 않는다.
- 첫 중간 산출물은 샘플 데이터로 주요 화면을 확인할 수 있는 UI다. 실제 호출·영구 저장을 지원하는 버전과 구분한다.
- 최초 사용 가능한 버전은 API 생성 → 저장 → 환경 선택 → payload 세트 선택 → 실제 호출 → 응답 확인 → 외부 Git 공유가 연결되어야 한다.
- 이후 문서 작성과 선언형 테스트·일괄 실행을 추가한다. 파일 포맷에는 후속 기능을 위한 버전 관리 기준을 처음부터 둔다.
- 모크 데이터 생성·API 대량 등록·삭제·초기화와 해당 UI는 보류하며 최초 사용 가능한 버전의 필수 범위에 포함하지 않는다.
- 공개 배포 전에 대상 버전의 기능 검증과 설치·이전·문서 작업을 완료한다.

## 5. 구현 전에 확정할 사항

1. 실제 HTTP 실행·업로드 IPC와 Windows 설치/업데이트 방식. 작업 폴더·개인 저장소는 IPC 계약을 따른다. 개인 DB의 구체 JSON 스키마·보관 정책·백업/마이그레이션, 서비스별 크기 상한·복구 저널의 디스크 처리와 Windows 파일 경합 검증을 구현 전에 구체화한다. 앱 런타임·빌드 기준은 1절과 PC 앱 설계를 따른다.
2. 앱 내부 JSON 검증 라이브러리·Windows 설치 프로그램 생성 도구의 도입 여부와 호환 버전. 공유 파일 형식은 01.06의 포맷 v1로 확정돼 있으며 UI 모델 변환·실제 저장/복구를 구현해야 한다.
3. 대상 API의 리다이렉트·TLS·쿠키 정책, 환경 변수 우선순위와 비밀값 영구 보관 여부.
4. SQLite 개인 실행 이력의 응답 보관 범위·기간·용량. API 저장 이력과 실행 이력은 별도 데이터로 관리한다.
5. 후속 문서 UI·Excel 검증 시 Electron 설치본에서 저장 위치 선택·파일 출력과 실제 Excel 화면 표시를 확인한다. 보류한 모크 기능의 호출 간격·동시 실행·삭제 API 매핑 정책은 재개 시 확정한다.
