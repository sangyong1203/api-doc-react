# API Doc 개발 기획

작성일: 2026-11-12

## 1. 목적과 확정 방향

개발자가 REST API를 등록·호출·문서화·테스트하고, 여러 요청 데이터 세트를 재사용하며, API 자료를 Git으로 공유하는 도구를 개발한다. `frontend-vue`는 기능 이해를 위한 참고 자료로 활용하며, React 버전은 `frontend-react`에서 개발한다. UI·사용 흐름·폴더 구조·구현 방식은 최신 개발 기획과 React 환경에 맞게 설계한다.

- 프런트엔드는 React + TypeScript + Vite로 개발하고, UI는 shadcn/ui를 사용한다.
- UI 추가 라이브러리는 Tailwind CSS(스타일), Lucide React(아이콘), React Router(라우팅), CodeMirror(JSON·text·문서 원문 편집)를 사용한다. UI 상태는 React 기본 상태로 시작한다. 패키지 버전은 개발 환경 구성 시 상호 호환성을 확인하고 `package.json`과 lockfile에 기록한다.
- 사용자는 HTTPS 웹 주소로 API Doc에 접속한다. 웹 호스팅은 화면 파일을 제공하고, 사용자 PC에 설치한 로컬 에이전트는 API 호출·로컬 파일 접근·모크 데이터 대량 등록 작업을 수행한다.
- 웹 접속 후 에이전트 연결 상태를 확인한다. 연결되지 않으면 설치·실행 방법과 다운로드를 안내한다. 연결 승인 후 사용자 작업 폴더를 선택하여 사용한다.
- 웹 UI와 에이전트는 별도로 배포·업데이트하며, 상호 호환되는 버전을 확인한다.
- 에이전트 런타임은 Node.js로 확정하고, 최초 배포는 Windows를 지원한다. 향후 macOS도 지원할 수 있도록 API 호출·파일 포맷·데이터 생성 등 공통 코드와 트레이·자동 실행·자격 증명 저장·설치·업데이트 등 OS별 처리를 구분한다. 공통 코드 기반으로 Windows와 macOS용 설치 파일을 각각 제공하는 방향이며, macOS 구현·검증·배포는 후속 범위다.
- 사용자 정보·설정·API 데이터는 사용자 PC와 사용자가 선택한 Git 저장소에서 관리한다.
- API 정의·폴더 구조·문서·payload 세트·공유 환경 템플릿은 사용자 작업 폴더의 파일로 저장한다. 사용자는 외부 Git 도구로 해당 파일을 관리·공유한다.
- IndexedDB에는 테마·선택 환경·열린 탭 등 개인 설정과 저장 전 편집 초안을 보관한다.
- 실제 비밀번호·토큰 등 비밀값은 공유 파일에 기록하지 않는다. 비밀값의 보관 방식은 별도 기술 설계에서 확정한다.
- 모크 데이터 대량 등록은 데이터를 생성하고 미리보기에서 확인한 뒤, 각 데이터를 지정한 등록 API의 요청에 매핑하여 반복 호출하는 기능이다. 예를 들어 로봇 데이터 1,000건을 생성하면 로봇 등록 API를 1,000번 호출한다. 생성 데이터 삭제와 전체 초기화도 사용자가 지정한 삭제·초기화 API를 통해 수행하며, 실제 DB 변경 범위는 해당 API가 담당한다.

- 개발 순서는 아래 단계 요약의 행 순서를 따른다. 기능 번호는 추적용 고정 ID이므로 개발 순서와 다를 수 있다. UI 선행 단계의 기능 번호는 12다.
- UI 구조와 화면 흐름을 먼저 구현·확인한 뒤, 로컬 에이전트 및 작업 공간을 구현하고 실제 기능을 연결한다. UI 단계에서는 샘플 데이터와 메모리 상태를 사용하며, 실제 저장·호출 완료로 표시하지 않는다.
- 작업의 선행 조건을 충족하면 같은 단계 안에서 순서를 조정할 수 있다. UI 작업에 필요한 기술 선택을 먼저 진행하고, 파일 포맷·에이전트 세부 설계는 관련 실제 기능 구현 전에 확정한다.
- 결정이 필요한 항목은 결정 내용을 비고에 기록한 뒤 구현한다. 라이브러리·아키텍처 등 미확정 선택은 확정된 것으로 취급하지 않는다.
- 완료 시 관련 행의 상태와 비고를 함께 갱신한다. 전체 단계는 하위 항목이 모두 완료되거나 명시적으로 보류된 경우 완료로 표시한다.
- 기존 Vue 구현의 존재는 React 기능의 완료를 의미하지 않는다. 현재 상태는 React 버전 및 새 에이전트 기준이다.
- 단순 문서·스타일 수정은 가벼운 확인을 수행하고, TypeScript 로직 변경은 타입 검사, 실행 구조·빌드 설정 변경은 빌드를 포함해 검증한다. 기능별 중요한 실패 경로도 확인한다.

### 10. 모크 데이터 생성·API 대량 등록·초기화

## 4. 최초 사용 가능한 버전의 범위

- 개발 순서: 01의 UI 개발 기반 → 12의 UI 구조·화면 흐름 구현 및 확인 → 02의 로컬 에이전트·작업 공간 → 03~06의 실제 편집·환경·호출·세트 기능 연결. 09의 파일 공유 기반은 파일 저장 구현부터 함께 반영한다.
- 첫 중간 산출물은 에이전트 없이 샘플 데이터로 주요 화면을 확인할 수 있는 UI다. 실제 호출·영구 저장을 지원하는 버전과 구분한다.
- 최초 사용 가능한 버전은 API 생성 → 저장 → 환경 선택 → payload 세트 선택 → 실제 호출 → 응답 확인 → 외부 Git 공유가 연결되어야 한다.
- 이후 문서 작성과 선언형 테스트·일괄 실행을 추가한다. 파일 포맷에는 후속 기능을 위한 버전 관리 기준을 처음부터 둔다.
- 모크 데이터 생성·API 대량 등록은 REST 실행기를 재사용하여 별도 단계로 구현한다. 생성 데이터 삭제와 전체 초기화는 사용자 제공 API를 통해 수행한다.
- 공개 배포 전에 대상 버전의 기능 검증과 설치·이전·문서 작업을 완료한다.

## 5. 구현 전에 확정할 사항

1. HTTPS 웹 UI와 Node.js 에이전트의 로컬 연결 방식 및 Windows 설치·업데이트 방식. 런타임은 Node.js, 최초 OS는 Windows, UI는 별도 정적 웹사이트로 확정한다. macOS는 공통 코드 재사용을 고려하되 후속 배포 시점은 별도로 결정한다.
2. 승인된 UI 라이브러리의 호환 버전, 기능 단계별 데이터 검증·생성·저장 보조 라이브러리, API 저장 파일 형식과 구조.
3. 대량 등록의 호출 간격·동시 실행 상한·실패 시 계속/중단 정책의 기본값.
4. 실행 기록의 보관 위치·기간과 등록 ID 추출·삭제 API 매핑 설정. 생성 데이터 삭제와 전체 초기화 API 실행은 모두 제공한다.
5. Vue 엑셀 출력 기능의 이식 여부와 출력 항목.

위 항목은 해당 구현의 선행 결정이며, 미결정 항목과 무관한 조사·문서 작업은 진행할 수 있다.
