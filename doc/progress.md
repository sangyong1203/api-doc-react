#### 12.03 요청·응답 UI

상태: **진행 중**

shadcn 입력·선택·체크박스·표·탭·배지로 구성하며 요청 입력 탭과 요청·응답 뷰어는 Card 보드로 구분. 오른쪽은 Headers·Payload·Response 단일 탭으로 구성하고 기본 선택은 Response. Headers에는 Request URL·Request Headers·Response Headers를 제목·구분선·테두리가 있는 별도 영역으로 표시. Request URL은 실행 시 입력 주소와 직렬화된 Query를 합쳐 복사하며 현재 변수 치환 전임을 안내. 실제 호출 연동 시 변수 치환과 직렬화가 완료된 실제 전송 주소를 표시. 요청·응답 헤더를 나눠 표시하며 Payload에 실행 시작 시점의 활성 Path·Query와 Body 복사본을 표시하고 이후 편집과 독립적으로 유지. Payload의 Path·Query·본문도 Headers와 같은 제목·구분선·테두리 영역으로 구분. 없는 Path·Query·본문 영역은 제목과 함께 숨기며 빈 객체·배열 본문도 표시하지 않음. 현재 샘플 안내는 실제 호출 연결 전까지 유지. 응답 상태·시간·크기는 헤더 구분선 아래 각 탭 본문 상단에 왼쪽 정렬. 샘플 입력값이며 실제 전송·자동 헤더·변수 치환 전임을 표시. 브라우저에서 실행 후 본문·헤더·Query 수정 시 복사본 유지 및 단일 탭 전환 확인. 요청 제목·저장·메서드·주소·실행은 RequestToolbar, 입력 보드는 RequestEditor가 담당하며 페이지에서 조합. Path·Query·Body·Headers·Response·Docs 탭으로 구분. Response 내부는 공통 버튼형 보기 탭의 Success·Error로 구분하며 Success는 기존 응답 명세, Error는 상태 코드별 오류 응답 사례 편집을 제공하며 Path·Query 값은 별도 메모리 필드로 관리. 입력 필드 표는 중복 제목 없이 키·값 헤더 행에 테마 기반 배경색을 표시하며 오류 응답의 키·값 추가 버튼은 유지. Path·Query·Headers의 필드 추가 버튼은 Body와 같은 문구를 사용하며 각 탭 본문 테이블 오른쪽 상단에 배치. Response 내부 Success의 필드 추가와 Error의 오류 응답 추가는 하위 탭 오른쪽의 같은 위치에 배치. Response 표시는 성공 명세 또는 오류 사례가 있으면 데이터 설정 점을 표시. 오류 응답은 API별 여러 카드로 관리하며 각 카드에서 이름·HTTP 상태 코드·설명·본문 키/값을 편집하고 카드·행 삭제를 지원. 키·값 추가 버튼은 카드 내부에 배치하며 같은 상태 코드의 여러 사례를 허용. 변경은 미저장 표시 및 메모리 저장에 반영. 오류 응답은 문서용 예시이며 샘플 실행은 고정 성공 응답 표시. Vue EditDialog의 필드 명세 설계를 참고해 Path·Query·Headers에 필수·타입(string·number·boolean)·설명 컬럼 추가. Path는 필수·사용 고정이며 Query·Headers 중복 키는 허용. Query에는 array (string)·array (number)·array (boolean)을 추가하고 배열 행의 값 입력칸 오른쪽에만 키 반복(기본)·쉼표 구분 전송 방식 선택을 표시하며 별도 전송 방식 컬럼은 두지 않는다. 배열 값은 JSON 배열로 입력하고 원소 타입을 검증. API마다 입력 세트 1을 처음부터 제공하고 최소 한 세트를 유지. 팝업 상단은 입력 세트 목록 제목과 구분선으로 구성하며 선택 행은 테마 강조 배경을 사용. 이름 편집 입력칸은 소형으로 표시하고 가로 스크롤을 방지. 항목 이름을 선택하면 팝업을 닫는다. 오른쪽 별 아이콘으로 재열기 시 적용할 기본 세트를 지정하고 기본 배지를 표시. 선택한 세트의 입력은 요청 저장으로 반영하며 API 입력과 분리한다. 전환·삭제 시 미저장 입력 유실 확인. 선택·기본 세트 삭제 시 남은 기본 또는 첫 세트로 복귀. 브라우저에서 행 추가 왼쪽 배치·팝업 추가·이름 변경·기본 지정·기본 배지 표시 확인. 최신 UI에서 입력 세트 1 초기 제공·목록 제목과 구분선·별 아이콘·선택 배경·가로 스크롤 없음·항목 선택 후 닫힘 확인. 타입 검사·린트 통과. 브라우저에서 기본 세트의 입력값 저장 후 탭 재열기 복원, 선택·기본 세트 삭제 후 남은 세트 전환, 마지막 세트 삭제 비활성화, 미저장 전환·삭제 확인 취소 시 입력과 세트 보존, 다른 API의 세트 분리 및 API 탭 왕복 후 편집 유지 확인. 세트 삭제·미저장 전환·탭 닫기는 공통 Alert Dialog로 확인하고 취소·Escape 시 입력 보존 및 확인 후 실행을 브라우저에서 검증. UI 완료 기준 충족. 현재 메모리 기반이며 실제 변수 해석·파일 저장·호출은 04·06에서 연결. 포맷 v1은 세트 간 값 상속 없이 필드 ID에 대응하는 각 세트 값을 사용

#### 12.05 문서·테스트·이력 UI

상태: **진행 중**

Path·Query·Body와 같은 요청 입력 탭 목록에 Docs 탭을 제공하며 설명·요청 예시·응답 예시를 작성하고 상단 공통 저장 동작에 연결. #### 07.04 개별 API 엑셀 출력

상태: **검증 대기**

기존 xlsx 모듈 재사용. 현재 편집 내용 기준 API 단일 시트 생성. 실제 Excel 생성·재읽기 검증 통과. 병합 테두리용 셀은 빈 문자열로 출력하고 0·false를 보존하며 AZ 이후 열 주소와 테두리 없는 병합 범위 지원. 병합 영역 전체에 배경색·글꼴·정렬을 적용하고 지정 글자색은 테마색과 독립적으로 저장. 문서 상단 API 제목은 글자 크기 16·행 높이 36으로 표시. 섹션 제목(Headers·요청 위치별 명세·응답 명세·예시)은 연한 파란색(#DCE6F1), 필드 표의 컬럼 제목과 기본 정보 라벨은 연한 회색(#F2F2F2) 배경으로 구분. 요청·응답 예시 전체는 각각 한 행의 가로 병합 셀에 줄바꿈을 보존해 작성하고 행 높이는 Excel 상한 내에서 줄 수에 맞춤. 실제 XLSX 재읽기로 배경·굵기·크기·글꼴·글자색·정렬·테두리·행 높이를 검증. 실제 링크가 있는 셀만 하이퍼링크를 기록하며 빈 hyperlinks XML 요소를 생성하지 않도록 검증. 회귀 테스트 5건·타입 검사·빌드·해당 모듈 린트 통과. Electron 창·설치본에서 파일 저장 위치 선택·출력·오류 처리 및 실제 Excel 화면 확인 대기. 문서 UI 검증과 함께 후속 진행
